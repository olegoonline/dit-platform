# Партнёрская панель DIT — руководство

**Сайт:** `https://panel.dreamislands.org`
**Доступ:** логин и временный пароль приходят от администратора по WhatsApp или лично. Сменить пароль можно через ссылку «Magic link» на странице входа.

---

## Что такое партнёрская панель

Это рабочее пространство для управляющего одного объекта (property) — например, Tanya Samui. Здесь вы видите:

- **Программы**, которые проходят на вашем объекте, и агрегированную статистику по гостям
- **Гостей**, которые забронировали программы на вашем объекте (с фильтрами и редактированием)
- **Специалистов** вашего объекта — добавление, редактирование, история работы с гостями

Все данные жёстко привязаны к вашему property: вы **не видите** гостей, бронирований или специалистов других объектов. Это контролируется на уровне базы данных, ошибки доступа невозможны.

---

## Вход

1. Откройте `https://panel.dreamislands.org`
2. На странице входа есть две вкладки:
   - **Password** — обычный вход по email и паролю
   - **Magic link** — попросить одноразовую ссылку на email (если забыли пароль)
3. После входа автоматически попадёте на `/partner` — это раздел **Programs**

## Раздел «Programs» (`/partner`)

Что показывает: **программы, привязанные к вашему объекту**, и метрики по ним.

Колонки таблицы:
- **Program** — название и тип («composite» если программа объединяет несколько объектов)
- **Cohort** — целевая когорта (C1 Reset / C2 Performance / C3 Mind / C4 Immersion)
- **Tier** — уровень программы (RESET / REBUILD / TRANSFORM)
- **Completed** — сколько гостей завершили программу
- **Avg WBS Δ** — средняя дельта Wellness Baseline Score: разница между показателем гостя до и после программы. Положительное число = улучшение
- **Sample** — на скольких гостях посчитана дельта

Сверху три KPI-карточки: всего программ, всего завершённых бронирований, средневзвешенная дельта WBS.

Если карточка показывает «No property linked» — попросите администратора привязать ваш аккаунт к property через `/admin/team`.

## Раздел «Guests» (`/partner/guests`)

Что показывает: **гости, у которых есть бронирования на программах вашего объекта**. Если у гостя нет ни одного booking на вашем property — он не виден.

### Фильтры

Сверху таблицы два выпадающих списка:
- **Filter · Program** — оставляет только гостей с бронированием на выбранной программе
- **Filter · Property** — то же по объекту (если ваш property имеет sub-объекты типа клиники)

Очистить — крестик внутри выпадающего списка.

### Колонки

| Колонка | Что значит |
|---|---|
| Guest | Имя гостя + email |
| Country | Страна |
| Program | Все программы, на которые он(а) забронировался(ась) |
| Property | Все объекты, где проходили программы |
| Baseline | WBS из первичной анкеты (intake) |
| Latest stay Δ | pre_wbs → post_wbs последней брони и дельта |
| Cohort | Когорта, определённая по baseline WBS |
| Source | Откуда пришёл лид (wbs_form / cura / direct) |

### Открыть карточку гостя — клик по строке

Открывается модальное окно с двумя вкладками:

**Details** — поля, которые партнёр может изменить:
- Name
- WhatsApp
- Country

Поля **Email, WBS Score, Cohort, Source** видны, но заблокированы для редактирования. Менять их может только администратор.

**Revisions** — история изменений этого гостя. Каждое изменение от вас или администратора сохраняется навсегда: видно, какое поле меняли, с какого значения на какое, и когда. Это значит, что ваши правки **не уничтожают** старых данных — если что-то пошло не так, администратор может восстановить.

После «Save» строка таблицы обновляется автоматически.

## Раздел «Specialists» (`/partner/specialists`)

Здесь две таблицы:

### 1. Roster — управление специалистами

Кнопка **«Add specialist»** в правом верхнем углу — открывает форму:
- **Name** — имя специалиста (обязательно)
- **Role** — специализация (Medical Detox Lead, Performance Coach, etc.)
- **Cohort focus** — на каких когортах специализируется (мультивыбор C1–C4)
- **Active** — переключатель: активный специалист или ушёл/в отпуске

Кнопка **«Edit»** в строке — открывает ту же форму с заполненными полями.

Кнопка **«Card»** в строке — открывает карточку специалиста с подробной статистикой и списком гостей.

**Важно:** удалить специалиста полностью нельзя (это разрушит историю работы с гостями). Чтобы «убрать» специалиста — переключите **Active → off**.

### 2. Contribution — агрегированные метрики

Таблица показывает по каждому специалисту его outcome-метрики:
- Какую метрику отслеживает (wbs_delta, sleep_quality, energy_index, stress_score)
- Среднюю дельту по этой метрике
- Сколько раз измеряли (sample size)
- Когда последнее измерение

Это **анонимизированные** агрегаты — никаких идентификаторов гостей здесь нет.

## Карточка специалиста (`/partner/specialists/<id>`)

Открывается по кнопке «Card» в Roster.

Сверху профиль: имя, роль, специализация по когортам, статус, объект.

Три KPI-карточки:
- **Guests worked with** — уникальные гости
- **Completed stays** — сколько стэев завершено
- **Avg WBS Δ (completed)** — средняя дельта по завершённым стэям

Ниже — таблица **«Guests worked with»**: имя гостя, страна, даты стэя, статус, его роль в брони (например, «primary», «assistant»), пара pre/post WBS.

Сейчас таблица может быть пустой — связки «специалист ↔ бронирование» добавляются администратором при редактировании booking. Если связка пуста, попросите администратора заполнить.

## Что вы НЕ можете делать (по дизайну)

- **Видеть гостей другого property** — RLS базы данных отрежет даже при попытке прямого SQL-запроса
- **Менять WBS score, cohort, email, source гостя** — это поля только для admin
- **Удалять специалиста или гостя** — только soft delete через `Active → off`
- **Двигать статус брони** (inquiry → confirmed → active → completed) — это делает admin через `/admin/bookings`. Если нужно зафиксировать переход — напишите admin'у с booking ID

## FAQ

**Я не вижу гостя, который должен быть у меня.** Проверьте: у этого гостя точно есть booking на программу, привязанную к вашему property? Если booking есть, но property не привязан к программе — попросите admin исправить в `/admin/programs`.

**Я случайно поменял имя гостя на неправильное.** Откройте этого гостя → вкладка **Revisions** → попросите admin'а восстановить из последней корректной записи.

**Гость говорит, что не получил magic-link.** Проверьте email — папка «Спам». Если письма нет совсем — попросите admin'а проверить настройки SMTP в Supabase.

**Я добавил специалиста, но он не появляется в Contribution.** Contribution table заполняется только когда есть `specialist_outcomes` (записи о результатах работы). Это пока вводит admin вручную после стэя.

**Хочу убрать специалиста — он уволился.** Edit → **Active → off**. Он останется в истории `Guests worked with` и Revisions, но не появится в дропдаунах при привязке к новым бронированиям.

**Я забыл пароль.** На странице входа переключитесь на вкладку **Magic link** → введите свой email → перейдите по ссылке из письма. Войдёте без пароля и сможете попросить admin'а выдать новый.
